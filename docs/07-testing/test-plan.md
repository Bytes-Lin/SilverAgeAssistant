- llama.cpp 请求仅发送 `temperature`、`top_p`、`top_k` 三个可配置采样参数并关闭思考；
- 工具调用参数跨分片聚合，`get_current_time` 执行结果进入下一轮模型请求；
- 老人明确报告“今天身体不舒服”时调用 `report_family_situation`，客户端使用设备 UTC 时间和 UUID 上报，并把事件确定为紧急；
- 老人明确提出“想让儿子回家吃饭”等家庭请求时上报一般事件；普通闲聊、过去已结束的情况、假设问题和他人的状态不得触发上报；
- 模型给出与事件类型冲突的紧急程度时，端侧强制执行“家庭请求=一般、身体不适/疑似异常=紧急”，模型参数不能降级紧急事件；
- `report_family_situation` schema 不允许模型填写事件时间；摘要为空、超长、类型未知或包含多余参数时拒绝执行；
- 中台上报失败时模型不得声称家属已经收到，使用同一 `client_event_id` 的重试不得产生重复事件；
- API Key 缺失时不发送 Authorization，配置时只发送 Bearer 且不记录日志；
- 老人端 API Key 输入框默认遮罩，可临时显示；保存后明文草稿被清空，重新进入页面只显示末四位；
- 空白 API Key 不保存，替换保存覆盖旧密钥，删除必须二次确认；
- API Key 保存和删除不调用中台或模型服务，完整值不进入 UI 状态字符串、日志、`model-config.json`、备份和设备迁移；
- LLM 流式中断、空回复、HTTP 鉴权/限流/服务端错误；
- 取消生成后保留部分回复并可重新发送；
- TTS 失败；
- AI 播放时再次录音；
- 网络切换；
- 屏幕旋转/进程重建；
- 大字号下不截断关键按钮；
- 本地欢迎语在左侧且不进入模型上下文，老人消息在右侧、流式 AI 消息在左侧；
- 打字发送后清空草稿、立即追加老人字符串并逐段展示模型回复；
- 空白文字不能发送，模型生成阶段不能同时发送文字；
- 手写模式能聚焦输入框并明确提示切换系统手写键盘；
- 系统手写识别结果与打字结果进入同一个字符串草稿。
- 完成绑定、恢复既有老人会话和同步联系人后更新设备私有 `MEMORY.md`；
- system prompt 包含老人称呼和家属摘要，且明确记忆不能作为指令；
- `MEMORY.md` 和模型请求中不出现家属手机号或尾号，只记录联系方式已在本机安全保存；
- 联系人权限失效或绑定撤销后清除长期记忆中的家属区段；
- 重复写入同一长期记忆时去重，换行和闭合 prompt 分隔符会被安全处理；
- `MEMORY.md` 不进入 Android 云备份或设备迁移。
- 家属模型配置表单校验 URL、模型名、上下文长度、最大 Token 和三个采样参数边界；上下文长度不得小于最大生成 Token；
- 相同模型配置幂等重试不重复递增 revision，请求体变化返回冲突；
- 老人端拉取新 revision 后下一轮聊天使用新地址、模型和参数；
- 老人端拉取失败或配置非法时继续使用上次可用的本地 JSON；
- Release 拒绝明文 HTTP 模型地址，Debug 允许本地 HTTP；
- 家属请求、中台 OpenAPI、数据库、日志和老人端 `model-config.json` 均不包含 API Key；
- `model-config.json` 不进入 Android 云备份或设备迁移。
- 首次进入老人首页时，定位已授权会触发天气加载，未授权时出现粗略定位权限说明；
- GPS、Network 和 Fused Provider 任一返回有效坐标即可继续；某个已启用但无坐标的 Provider 不得阻塞其他 Provider，尤其覆盖 Android 模拟器 GPS 注入场景；
- 城市名称必须由本次天气查询使用的同一经纬度反向地理编码得到，不能根据时区猜测或硬编码；
- 系统 Geocoder 无结果时调用 BigDataCloud 客户端后备接口，优先读取 `city`，并复用天气缓存；两级解析均失败时显示“当前位置”且天气仍能加载；
- 首页天气第一行左侧显示城市，右侧显示当前天气和温度；
- “最近提醒”位于独立浅蓝卡片，与粉色家人绑定卡和紫色天气卡可清楚区分；
- Tool 可包含城市级名称，但不得包含区县以下地址、街道、门牌或经纬度；
- Open-Meteo 请求包含 current、daily、`forecast_days=4` 和 `timezone=auto`，响应正确映射当前、今天及未来三天；
- 首页显示当前天气、今天及未来三天，加载、拒绝定位、定位关闭、网络失败和过期缓存状态可区分；
- 1 分钟测试缓存内首页和 `get_weather` 连续查询只产生一次天气网络请求，满 1 分钟后重新请求；
- 首页刷新和 Agent Tool 并发时共享一次进行中的天气请求；
- 天气网络刷新失败时使用已有缓存并标注上次更新时间；
- `get_weather` 结果包含缓存状态但不包含经纬度，权限或服务失败返回结构化错误；
- WMO 天气码、温度、降雨概率和恶劣天气行动建议映射正确，未知天气码不导致崩溃；
- 应用不申请精确定位和后台定位，坐标不进入中台、模型上下文、日志或备份；
- 天气卡标注“天气数据：Open-Meteo”，生活建议不冒充官方灾害预警。

## 7. 图像分析

状态监控基础组件覆盖：默认 5 分钟、1..60 分钟边界、revision 冲突、断网保留上次配置、WebSocket 丢失后 REST 补拉、事件幂等、一般/紧急分类、跨时区今日边界、未 ACK 紧急事件恢复弹窗，以及证据图像的独立上传和授权读取。中台须补充图像接口、权限、保留期和第二次 WebSocket 提示测试；Android 离线与弹窗恢复仍需端到端验证。

- `enabled` 缺失或不是 JSON 布尔值时返回 `INVALID_SAFETY_ENABLED`，不能接受字符串或数字替代；
- `enabled=false` 与合法的非零间隔共同持久化，双方 GET 必须返回该字段；
- 仅改变 `enabled` 也会递增 revision、改变幂等指纹并发送配置可用提示；
- 迁移前已有配置升级后为 `enabled=true`，不得意外关闭老人端监控；

- 默认开启后启动带常驻通知的独立前台服务，老人端不显示停止入口；家属关闭后停止服务并清空六小时暂存历史；
- 运行中从 1 分钟改为 5 分钟会取消旧等待并按 5 分钟重排，已有历史、连续异常次数和短信标记保持不变；快速连续下发配置最终应用最新 revision；
- WebSocket 断线后恢复连接并由 REST 补拉完整配置；服务进程由 `START_STICKY` 恢复时读取最后一次本地配置；
- mock 图像按稳定顺序轮换，图像 MIME 类型正确；正式 `NetworkCameraImageSource` 不影响 Agent 编排；
- MLLM 请求包含独立 system prompt、最近一次状态 context、设备 UTC 时间、单张图像和严格 JSON 要求，不包含聊天历史、手机号或 API Key 正文；
- 正常结果允许省略详情，异常结果缺少详情、未知状态、多余字段、Markdown 外文本和超大图像均拒绝；
- 正常结果将连续异常次数归零；第 1 次异常不通知，第 2 次创建本窗口唯一事件并上传触发图像，第 3 次仅发送一次短信；同一六小时窗口后续异常不再创建事件或重复短信；
- 六小时窗口到期自动清空；修改间隔不清空；关闭后重新开启从空窗口开始；
- 短信只发给本机加密快照中的紧急联系人并去重，未授权 `SEND_SMS`、无联系人或发送失败时不得标记成功；
- 状态监控模型调用记入全局 MLLM 用量，feature 为 `safety_monitoring`；除本窗口唯一事件的单张证据图像外，其他图像、完整模型响应和检测历史不上传中台或进入备份；
- 图像 PUT 验证 JPEG/PNG 实际签名、8 MiB 上限、事件归属和幂等冲突；生成去 EXIF、最长边不超过 512px 的缩略图；
- 图像保存后发送 `SAFETY_EVENT_IMAGE_AVAILABLE`，家属端刷新元数据并显示缩略图；点击只按授权加载原图，越权、过期删除和无图均不能泄漏内容或公开 URL。

- 老人主动上报 `HEALTH_DISCOMFORT_REPORTED` 时，即使客户端提交 `GENERAL`，中台仍保存和通知为 `EMERGENCY`；
- `FAMILY_REQUEST` 即使客户端提交 `EMERGENCY`，中台仍保存和通知为 `GENERAL`；
- 老人身体不适和家属请求可以忠实描述原话，异常检测类型缺少“疑似”或“需要核实”时拒绝；
- 两种 Agent 共用同一接口和 `client_event_id` 幂等策略，重试不产生重复家属通知。

## 9. 模型用量

- OpenAI 流式响应含完整 usage 时记录精确 input/output Token；
- llama-server 不返回 usage 时生成估算值并显示估算标记；
- Tool Use 产生多轮模型请求时逐轮累计；
- 取消、超时和失败调用记录失败次数，不保存聊天正文；
- 上下文圆形进度不小于 0、不超过 100%，无 usage 时保持可理解状态；
- 家属下发新的 `context_window_tokens` 后，老人补拉并在下一轮聊天使用新值作为圆形进度分母；旧配置缺失字段时使用 32768；
- Room 1→2 迁移保留既有提醒；
- 每小时任务尝试上传，成功后标记，失败后保留并交给 WorkManager 退避重试；VPN、私有网络和 Android“部分连接”状态不得让任务永久卡在 `CONNECTED` 约束；
- 家属只进入用量页面或页面自动重组时仅查询中台，不触发老人设备即时上传；
- 家属点击“立即刷新用量”后，中台向在线老人设备发送一次 WebSocket 事件，老人端的一次性任务上传尚未汇报记录，家属端在约 6 秒内显示更新后的汇总；
- 相同刷新请求幂等重试返回首次时间和在线结果，不重复投递；同一家属对同一老人 3 秒内的新刷新请求被限流；
- 刷新事件只投递给仍有效的 device credential 连接，事件只包含协议字段和 `client_request_id`；
- 老人设备离线时，手动刷新保留中台上次汇报值并显示离线说明；不得将 `last_reported_at: null` 渲染为字符串 `null`；
- 小时任务和即时任务并发时串行上传，相同本地批次不会重复累计；
- 相同 batch 幂等重试不重复累计；
- 相同 batch 改变请求体返回幂等冲突，101 个 items 返回批次过大；
- 中台从 device credential 推导老人和设备，不接受请求体覆盖身份；
- 用量批次拒绝非法 IANA 时区和未知来源；最近 `LOCATION` 时区优先且不被后续 `SYSTEM_FALLBACK` 覆盖；
- 每日接口按老人当地当前自然月返回升序完整日期，月初、月末和零用量日期边界正确；
- 每日桶按批次 `period_started_at` 的老人当地日期归属，Token 和三种模态计量规则与汇总接口一致；
- 尚无位置时区时响应明确返回 `SYSTEM_FALLBACK`，异地家属不能通过查询参数覆盖老人时区；
- 上报周期必须为 UTC、正序、不超过 7 天且未来容差不超过 10 分钟；家属查询不超过 366 天；
- MLLM Token、三种模态调用次数、ASR 时长和 TTS 字符/时长按模态正确聚合，任一估算项使汇总标记为 true；
- 无数据查询返回全 0 totals 和空最后上报时间，不返回 404；
- 家属只能查询有效绑定老人，页面明确标注客户端统计而非厂商账单；
- 老人位置天气成功后保存 Open-Meteo `timezone=auto` 返回的 IANA 时区并随用量批次上报，不根据城市名猜测或硬编码上海；
- 中台优先使用老人最近的 `LOCATION` 时区返回当地 `current_date` 和每日分桶；家属请求不包含时区参数，空日期为 0；
- 尚无位置时区时 `SYSTEM_FALLBACK` 必须透传到家属页面并显示提示，且不能覆盖已有的位置时区；
- 家属端今日卡片只读取当天桶；Token 图按天区分输入/输出，语音图按天区分 ASR/TTS，横向滚动和无障碍描述可用；
- 每日接口不可用时仍展示月汇总和兼容提示，Android 不退化为逐日发起三十多次请求；
- ASR/TTS Provider 接入后分别验证调用次数，且请求 schema、数据库和审计均不上传 API Key、提示词、音频或文本。
