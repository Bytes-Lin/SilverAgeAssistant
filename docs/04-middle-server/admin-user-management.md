# 中台用户管理后台

## 1. 范围

轻量阶段的中台管理页面只用于排查账号和绑定状态，不作为业务数据运营平台。

允许查询：

- 家属账号称呼、脱敏手机号和启用状态；
- 该家属绑定的老人称呼、脱敏手机号、关系和账号状态；
- 每条绑定的有效老人设备数量、绑定状态和绑定时间。

明确禁止查询或展示：

- 通知、提醒及其正文；
- 安全事件、摘要和证据图像；
- 模型及语音配置；
- 模型用量；
- 聊天、长期记忆和端侧文件；
- API Key、JWT、Refresh Token、device credential 或其摘要；
- 完整手机号、绑定码和设备外部标识；
- 任意 SQL、整库浏览和批量导出。

管理页面允许修改有效绑定的家属称呼、老人称呼和关系。手机号承担账号和绑定身份，不允许
在管理页直接修改。每张绑定卡片提供一次彻底删除入口；管理员必须输入该卡片对应的家属
完整手机号进行二次确认。确认成功后物理删除该家属账号、其创建的全部老人档案及相关中台
数据，从而释放手机号并允许 App 重新注册。

## 2. 隐私与交互规则

- 登录后默认展示全部家属—老人绑定对（包含已撤销记录），也可按双方姓名或完整手机号筛选；
- 完整手机号仅用于服务端精确匹配，响应只返回数据库中的脱敏号码；
- 搜索使用 `POST` 表单，完整手机号不进入 URL、浏览器历史或 Referer；
- 姓名中的 `%`、`_` 等字符按普通文本处理，不能作为 SQL 通配符枚举用户；
- 已撤销绑定明确标记状态且不可编辑，但仍可执行彻底删除，避免软撤销后无法释放手机号；
- 页面使用 `Cache-Control: no-store`、CSP、`X-Frame-Options: DENY` 和
  `Referrer-Policy: no-referrer`；
- 管理路由不进入 OpenAPI，普通 API 启动时默认关闭，并且只接受服务端看到的回环地址连接；不信任
  `X-Forwarded-For` 绕过限制。

## 3. 本地启用

在 `MiddleServer` 目录运行：

```powershell
.\.venv\Scripts\python.exe -m app.admin_launcher
```

该命令仅监听 `127.0.0.1:8000`，默认不自动打开浏览器。登录页面为
`http://127.0.0.1:8000/admin`。

可以通过参数修改本机回环地址和端口，例如改用 8765：

```powershell
.\.venv\Scripts\python.exe -m app.admin_launcher --host 127.0.0.1 --port 8765
```

此时登录页面为 `http://127.0.0.1:8765/admin`。如果希望启动后自动打开浏览器：

```powershell
.\.venv\Scripts\python.exe -m app.admin_launcher --port 8765 --open-browser
```

如果需要老人端和家属端从其他设备连接同一个 FastAPI 中台，可监听所有 IPv4 网卡：

```powershell
.\.venv\Scripts\python.exe -m app.admin_launcher --host 0.0.0.0 --port 8765
```

Android 端应配置实际可达的局域网 IP、公网 IP 或域名，例如
`http://203.0.113.10:8765`，不能配置 `0.0.0.0`。管理页面仍只允许请求来源为本机回环地址，
外部设备访问 `/admin` 返回 404；业务 `/api/v1/*` 和 `/api/v1/ws` 则可从外部连接。

直接通过公网提供服务时必须配置系统/云防火墙、NAT 或端口映射，并使用 HTTPS/WSS。更推荐
让 FastAPI 继续监听本机或内网地址，由具备 TLS 的反向代理仅公开业务 API；反向代理必须
明确阻断 `/admin`，不能把管理页面转发到公网。

`app.admin_launcher` 不是第二个应用：它创建与 `app.main` 相同的 FastAPI 应用对象，只是在
启动前打开管理功能。业务 API、WebSocket、管理页面和 SQLite 数据库位于同一进程。监听
`0.0.0.0` 只是让业务接口接受外部连接，不会让远端请求通过 `/admin` 的回环来源校验。

内置两个同权限开发管理员：

```text
admin / Ace@0101
test  / Ace@0101
```

登录采用 HttpOnly、SameSite=Strict 的本机会话 Cookie。源码中只内置 PBKDF2 密码校验摘要，
不保存或回显密码明文。内置凭据只允许在 `development` 环境启用；不得通过公网反向代理发布
该路径。未来如需远程或生产管理，必须删除内置账号，重新设计 HTTPS、管理员数据库、密码
轮换、多因素认证、操作审计和登录速率限制。

## 4. 管理操作语义

### 修改

- 可修改家属称呼、老人称呼及当前绑定关系；
- 手机号只读，不允许绕过账号唯一性和绑定验证直接修改；
- 关系只接受 `CHILD`、`RELATIVE`、`CAREGIVER`、`OTHER`；
- 更新在绑定写锁和单个数据库事务中完成，并写入 `ADMIN_BINDING_UPDATED` 审计记录；
- 页面使用会话内随机操作句柄，不向 HTML 暴露数据库 binding ID。

### 彻底删除用户数据

- 删除入口直接位于绑定卡片，不再提供独立的 `RESET` 区域或重置接口；
- 管理员必须输入家属完整手机号，服务端规范化后与卡片关联账号做精确、等值校验；
- 一个家属可能创建多个老人档案，因此删除范围是该家属账号及其创建的全部老人，而非只删除
  当前卡片中的一条绑定；页面必须在确认框上方说明这一影响范围；
- 在绑定写锁与单个数据库事务内，按外键依赖顺序物理删除绑定码、绑定、设备凭据、通知和提醒、
  模型配置与用量、安全监测配置与事件、图像元数据、处理请求、关联幂等索引和旧资源审计；
- 数据库提交成功后删除安全事件的私有原图和缩略图，并关闭该家属与老人设备的现有 WebSocket；
- 最后仅保留一条 `ADMIN_USER_DATA_DELETED` 管理审计，不记录手机号或已删除资源 ID，只记录
  管理员账号和删除数量；
- 操作不可恢复；成功后家属端可用原手机号重新注册、创建老人档案并绑定设备。

## 5. 当前限制

- 仅用于 development 单机阶段，不能作为公网生产管理系统；
- 管理会话保存在单进程内存，服务重启后失效，不支持多 worker；
- 内置 `admin`、`test` 账号权限相同，不具备细粒度 RBAC；
- 暂无登录失败限流、多因素认证、密码轮换和管理员数据库；
- 页面不提供手机号修改、历史绑定恢复、数据导出或任意 SQL。
- 物理删除用于当前开发/正式版联调清理，不等同于已经完成面向生产用户的账号注销合规流程。
