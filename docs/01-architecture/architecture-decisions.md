# 架构决策记录

本文件汇总当前已经确认、开发时不得自行改变的关键决策。需要修改时，应先更新本文档并说明迁移影响。

## ADR-001：单 APK 双角色

同一个 Android 应用包含老人模式和家属模式。两种角色共享基础网络、身份和数据模型，但采用独立导航和 UI。

## ADR-002：Android 10 为最低版本

`minSdk = 29`。这表示应用支持 Android 10 及以上版本，不代表 `targetSdk` 固定为 29。

## ADR-003：老人端直连模型服务

每位老人使用自己开通的模型 API Key。老人端直接连接云端 MLLM、ASR 和 TTS，减少实时语音链路的中转时延。

约束：

- API Key 使用 Android Keystore + AES-GCM 本地加密；
- 不上传 MiddleServer；
- 不写入日志、崩溃报告和 Git；
- 家属端只能查看配置状态、掩码和本地上报的用量估算。

## ADR-004：FastAPI 只负责家庭协同

MiddleServer 使用 FastAPI，负责账号、绑定、事件、远程提醒、SOS、审批、用量上报和同步，不代理日常模型请求。

## ADR-005：REST + WebSocket，不接移动推送

- REST 是业务事实来源，用于可靠写入、查询、ACK 和断线补拉；
- WebSocket 用于客户端在线时实时通知；
- 不使用 EMAS、FCM 等推送服务；
- 客户端后台或被系统终止时不保证即时送达。

## ADR-006：本地提醒优先

提醒定义和触发记录存老人端 Room。本地 AlarmManager/WorkManager 负责触发；服务器只同步家属指令和老人确认结果。

## ADR-007：Agent 受确定性策略约束

MLLM 只能提出 Tool Call，不能直接操作系统。Policy Engine 根据工具、金额、权限、ASR 置信度和当前状态决定允许、确认、家属审批或阻止。

## ADR-008：支付和医疗安全边界

- 所有付费订单至少一次明确确认；
- 超过阈值进行二次确认或家属审批；
- Agent 不读取或输入密码、验证码和生物识别；
- 系统不进行医疗诊断、不修改药物剂量。

## ADR-009：跌倒检测仅保留接口

MVP 只提供图像上传至 MLLM 和结构化风险结果展示，不实现持续监控，不宣称可靠跌倒检测，不根据单次模型结果自动拨打急救电话。

## ADR-010：SOS 本地优先

SOS 触发后，本地拨号、短信或位置处理与服务器事件并行执行。服务器故障不得阻塞本地求救路径。

## ADR-011：中台首版采用 SQLite 并按里程碑开发

Android 双角色基础 UI 完成后，FastAPI 中台已进入 M04，并首先实现家属注册与老人设备绑定。中台首版使用 SQLite 和单进程 FastAPI，不引入 PostgreSQL、Redis 或对应 Docker 基础设施。可靠业务状态写入 SQLite；WebSocket 连接映射等可丢失的短期状态可保存在进程内存。

若后续需要多实例部署、跨进程实时投递或更高并发写入，应先评估并记录数据库及缓存迁移方案，不在当前阶段预先建设。
