# 家属模式设计

## 1. 目标

家属端提供必要协助，而不是全面监控老人隐私。状态来源必须可解释，并显示最后更新时间。

## 2. 功能

### 绑定与配置

- 登录；
- 创建老人档案；
- 生成绑定码/二维码；
- 设置关系、优先级和紧急联系方式；
- 设置支付二次确认阈值；
- 协助配置老人模型 API Key，但 Key 只在老人设备输入/保存。
- 设置老人端模型服务地址、模型名、协议方言、上下文长度、最大生成 Token 和采样参数；非敏感配置可通过中台下发。

### 状态查看

- 最近活跃时间；
- 设备最近同步时间；
- 提醒确认事件；
- 老人主动报平安；
- SOS 和异常事件；
- 模型用量估算。

状态语义：

- “已确认服药”：老人点击或语音确认；
- “暂未确认”：没有收到确认；
- 不使用“确定已服药/未服药”等无法验证结论。

### 向老人发送内容

- 即时文字/语音播报通知；
- 一次性提醒；
- 周期提醒指令；
- 请求回电；
- 高风险订单同意/拒绝。

指令先保存在服务器，老人端在线时通过 WebSocket提示，再通过 REST 获取完整内容并 ACK。

当前 Android 已实现即时文字通知和一次性提醒表单。提醒日期与时间使用系统选择窗口，不允许手工输入；日期不得早于今天，同日时间必须严格晚于当前时刻，选择时即时拒绝并在提交前再次校验。提交必须包含中台返回的老人档案 ID 和稳定 `client_request_id`；失败后保留表单并复用同一幂等 ID，收到中台成功响应后才显示“已交给中台”。

老人端在启动及进入“今日提醒”时补拉命令。通知以“家人通知”写入当天提醒；远程提醒沿用中台 `scheduled_at` 字段传输家属设置的完成截止时间。两类命令均先以 `command_id` 幂等写入 Room，再发送 `STORED` ACK；ACK 失败会保留本地待确认状态并在下次同步重试。

老人端“今日提醒”按事件时间升序展示未完成与稍后提醒，已完成项目统一置底；等待确认、稍后提醒和已完成分别使用普通、强调和弱化背景，避免稍后提醒与完成状态混淆。新的家属提醒首次按 `command_id` 写入 Room 后，老人端立即发布包含标题、内容和截止时间的系统通知；REST 重复补拉不会重复弹出。该收件通知与截止时间开始的每小时催办通知相互独立。

老人明确点击“我已完成”后先写入本地 Room。远程提醒生成稳定幂等完成请求并向中台回传；断网时保留待同步状态，在后续命令同步时重试。家属端“提醒记录”读取中台聚合状态，区分等待设备接收、尚未确认完成和已确认完成。即时通知不进入完成回传。

每条未完成远程提醒在截止时间启动唯一 WorkManager 周期任务，并通过高优先级本地通知提醒老人；仍未确认时每 1 小时重复一次。老人确认完成后立即取消该任务。应用启动时会为 Room 中未完成提醒补做去重调度，WorkManager 可跨进程退出和设备重启保留任务，但受系统省电策略影响时允许延迟，不承诺秒级准点。Android 13 及以上在老人角色恢复后就地申请通知权限；拒绝权限不影响提醒数据和完成状态，只会暂时无法弹出系统通知。

未完成提醒一经写入 Room 即持续显示，不再按截止日期过滤，因此未来截止、跨时区换算或逾期不会表现为“未收到”；完成项仅在老人确认完成的当天保留。当前家属端使用自身设备系统时区解释日期和时间，跨时区联调前应确认两端时区一致；正式方案待中台同步老人设备 IANA 时区供家属端使用。

老人端“联系家人”只展示中台按有效绑定同步的真实联系人，不再使用测试姓名和测试号码。完整手机号仅通过 device credential 保护的专用接口读取，并以 Android Keystore AES-GCM 加密快照离线保存；点击号码进入系统拨号页。中台接口契约见 [`../04-middle-server/elder-family-profile-sync-requirements.md`](../04-middle-server/elder-family-profile-sync-requirements.md)。

### 用量监控

老人端直接调用模型，因此家属端看到的是客户端上报的统计/估算：

- ASR 调用次数；
- LLM 输入/输出 Token（可获取时）；
- TTS 调用次数；
- 请求次数；
- 本地估算费用；
- 每日/月度阈值。

不得把该数据标为云厂商正式账单。

Android 已实现家属端“模型用量”页面，默认查询当月汇总，展示 MLLM 输入/输出 Token、MLLM/ASR/TTS 调用次数、最后汇报时间和是否含本地估算。老人端本地账本通过唯一 WorkManager 任务每小时聚合汇报；中台未实现或网络失败时记录继续留在本地待重试。

进入页面只读取中台已有数据。家属明确点击“立即刷新用量”时，Android 先请求中台通知在线老人设备；老人端通过现有认证 WebSocket 接收 `MODEL_USAGE_REPORT_REQUESTED`，随后排入一次性 WorkManager 上传，家属端最多轮询约 6 秒。老人设备离线时显示上次汇报数据和离线说明。接口契约见 [`../04-middle-server/model-usage-reporting-requirements.md`](../04-middle-server/model-usage-reporting-requirements.md)。

用量页面新增“今日用量”和本月每日趋势。今日卡片展示聊天 Token、模型调用、ASR 和
TTS 次数；本月汇总保留总量文字。第一张横向可滚动柱状图按天堆叠输入/输出 Token，
第二张按天并列展示 ASR/TTS 次数，柱组提供无障碍文字说明。Android 一次请求中台已实现的
每日分桶接口并补齐当月零用量日期，不发起逐日查询风暴。

每日边界以老人手机位置为准，不以家属手机时区为准。老人端天气查询已经使用当前位置和
Open-Meteo `timezone=auto`，成功后将返回的 IANA 时区保存在本地，并随模型用量批次上报。
中台使用最近的位置时区返回老人当地 `current_date` 和自然月分桶，家属 Android 不发送
时区参数。位置时区尚不可用时才使用设备系统时区并标记 `SYSTEM_FALLBACK`，页面必须
显示降级提示，不得硬编码 `Asia/Shanghai`。

### 模型配置

家属首页提供“模型配置”入口。页面可读取和修改：

- OpenAI 兼容服务地址；
- 模型名称；
- `llama_cpp` 或标准 OpenAI 兼容方言；
- 上下文长度 Token；
- 最大生成 Token；
- `temperature`、`top_p`、`top_k`。
- ASR/TTS 共用的阿里云百炼 WebSocket 地址；
- ASR、TTS 模型名称，以及 TTS 音色、输出格式、采样率、音量、语速、音调和语言。

日常聊天思考模式固定关闭。配置由中台可靠保存，老人端在启动及进入聊天时使用 device credential 补拉；在线时收到 `MODEL_CONFIG_AVAILABLE` 后立即补拉。新配置通过校验后原子写入应用私有 `files/agent/model-config.json`，下一轮模型请求直接读取最新值，不要求老人重启应用。拉取失败保留上次可用配置。

API Key 不在家属页面填写、不经过中台，也不进入配置 JSON。ASR 和 TTS 共用一把语音
Key，在老人设备本机配置；其存储复用 MLLM Key 的 Keystore + AES-GCM 方案，但使用独立
凭证槽位。开发用无密钥服务可以直接使用远程非敏感配置。Android 已完成语音配置表单、
远程 JSON 映射、本地原子保存和老人补拉热更新；中台字段扩展完成后即可联调。接口扩展见
[`../04-middle-server/remote-model-configuration-requirements.md`](../04-middle-server/remote-model-configuration-requirements.md)。

## 3. 隐私边界

默认不展示：

- 完整聊天原文；
- 原始录音；
- 摄像头连续画面；
- API Key；
- 支付密码/验证码；
- 不必要的精确位置历史。

紧急事件可上传当前定位和有限摘要，但要记录用途和访问者。

## 4. 无推送服务下的体验

家属 App 前台连接时可实时收到 WebSocket 事件。后台或被杀后不保证实时：

- App 恢复时拉取未读事件；
- 周期 WorkManager 可补拉普通状态；
- SOS 同时由老人手机直接拨号/短信，不能把家属 App 通知作为唯一救援方式。

UI 必须显示“实时连接中/已断开”和“最后同步时间”。

通知与提醒采用低压力的“WebSocket 提示 + REST 可靠补拉”：老人端收到 `COMMAND_AVAILABLE`、WebSocket 首次连接或重连、应用返回前台时立即补拉一次；并发提示由 ViewModel 合并，Room 继续按 `command_id` 去重，不进行短周期轮询。家属端收到 `REMINDER_STATUS_CHANGED` 后自动刷新提醒记录，安全事件提示仍自动刷新今日状态和紧急事件；家属应用返回前台或 WebSocket 重连时也会补拉两类快照。手动刷新保留为网络异常兜底。

## 5. Android 初始化与绑定资料草案

当前 Android 已建立双角色初始化表单，并接入中台注册、老人档案、绑定码、设备绑定与绑定查询接口。

老人端资料：

- `display_name`：老人希望在界面中看到的称呼，必填，最多 20 个字符；
- `family_mobile_number`：生成绑定码的家属手机号，与绑定码共同校验，可稍后填写；
- `binding_code`：家属注册后由中台生成的 6 位数字码，可稍后填写；
- `sharing_consent`：手机号和绑定码填写完整时必须确认，只授权同步状态摘要、提醒确认和紧急事件。

家属端资料：

- `display_name`：家属称呼，必填，最多 20 个字符；
- `mobile_number`：用于后续家属登录和联系，当前 UI 按 11 位中国大陆手机号预检；
- `elder_display_name`：家属用于识别老人档案的称呼；
- `elder_mobile_number`：用于创建和识别老人档案，当前 UI 按 11 位中国大陆手机号预检；
- `relationship`：`Child|Relative|Caregiver|Other`，不提供“配偶”选项；
- `emergency_contact`：是否申请作为紧急联系人，最终权限由服务端绑定关系决定。

状态与失败路径：

- 无绑定码且无家属手机号：老人可先使用本地功能，状态为“尚未准备绑定”；
- 家属表单有效但中台不可用：状态为“等待中台注册并生成绑定码”；
- 老人端只填写手机号或只填写绑定码：停留在表单并提示补齐另一项；
- 老人端手机号、绑定码和共享确认均有效：状态为“等待中台联合校验”；
- 只有服务端验证账号、老人档案、设备和权限后，客户端才可显示“已绑定”；
- Debug 构建会把双方称呼、手机号、关系、紧急联系人选项和共享确认写入应用私有 DataStore，避免重复测试输入；该文件不参与云备份或设备迁移，Release 构建不启用。
- 绑定码、验证码、access/refresh token 和 device credential 不进入这份测试 DataStore；任何手机号均不得写日志。
- 家属提交有效资料后，Android 直接调用家属注册接口，再创建老人档案并生成绑定码；注册请求不包含 `verification_token`。老人提交“家属手机号 + 绑定码”后调用设备绑定接口。
- 家属端和老人端已在本地模拟器通过 `http://58.199.163.98:8765` 完成注册、生成绑定码和设备绑定联通验证。
- access/refresh token 与 device credential 使用 Android Keystore 生成的 AES-GCM 密钥加密保存，凭证文件和随机应用设备 ID 均排除云备份与设备迁移。
- 正式角色与初始化状态保存在独立的应用状态 DataStore 中，与仅用于 Debug 自动回填表单的测试资料分离；正式状态不保存手机号、绑定码或认证凭证。
- 重启应用时，完成初始化且存在加密凭证的角色直接进入首页，不重复调用注册或设备绑定接口；旧版本已保存的加密凭证会参与首次迁移恢复。
- 家属端进入首页及应用重新回到前台时调用绑定查询接口；access token 失效时使用 refresh token 刷新并重试。老人端使用 device credential 查询绑定。网络不可用时仍停留在首页并展示离线状态；中台明确返回凭证无效、绑定已撤销，或原已绑定角色查不到有效绑定时，清除对应角色状态并返回老人/家属身份选择页。若只是家属绑定被撤销而登录会话仍有效，则保留该会话和老人档案 ID，重新选择家属后复用原档案生成绑定码，避免重复注册已有手机号；认证失效才清除家属凭证。
- 家属首页提供“重新生成绑定码”，使用已保存的家属会话和老人档案 ID 再次调用 `POST /bindings/codes`。成功后显示新码但保留原“已绑定”状态，不误禁用通知和提醒入口。
- 家属首次生成绑定码后无需重启 App：若老人随后完成设备绑定，而当前页面仍保留“绑定码已生成”的旧状态，点击任何需要绑定的功能卡片会先实时调用绑定查询；中台确认已绑定后立即更新内存状态并继续打开原目标页面。尚未绑定或离线时不误开放跨端功能，并显示明确提示。
- 家属首页复用紧急事件 REST 数据展示最新一条尚未清除的紧急事件，包含事件类型、摘要、老人当地时间和醒目的紧急标识；点击卡片进入现有紧急事件列表查看图片并处理。中台没有未处理事件时显示“当前没有紧急事件”，加载失败时显示“暂未更新”而不误报平安；详情页清除事件后首页会同步显示下一条或空状态。
- 新发现的未确认紧急事件同时发布到 Android 系统通知栏，使用高优先级“家属紧急事件”通知渠道；同一事件 ID 在当前进程内只通知一次，WebSocket 重复提示和 REST 重复刷新不会生成通知风暴。Android 13 及以上在已登录家属端就地申请通知权限，拒绝后仍保留应用内首页卡片和紧急弹窗。
- 家属首页“提醒记录”入口紧跟在“创建提醒”之后。记录页自动沿中台 `next_cursor` 拉取全部分页，按截止时间从新到旧显示所有提醒；老人明确确认的记录标记“已完成”，其余统一标记“未完成”。
- 提醒记录的每张卡片提供“清除”按钮。Android 只有在中台家属账号级归档成功后才从列表移除，失败时保留原记录并显示错误；清除不删除老人端提醒、不改变完成状态，也不影响其他已绑定家属的视图。
- 中台已经支持已有绑定场景下的设备重新绑定：新设备使用新绑定码成功后原子轮换旧 device credential，契约见 [`../04-middle-server/device-rebinding-requirements.md`](../04-middle-server/device-rebinding-requirements.md)。

### 状态检测远程控制

家属端可选择“关闭状态检测”或 1/5/10/15/30/60 分钟。保存时同时提交独立的
`enabled` 和 `interval_minutes`；老人端收到 WebSocket 提示后立即 REST 补拉完整配置。
运行中修改间隔会即时重排下一次检测但保留六小时历史，关闭会清空历史并停止图像和
MLLM 分析。关闭后老人设备仍保持最小配置监听，以便家属再次开启时实时生效。

## 6. 本地中台联调地址

- 当前开发机中台地址配置为 `http://58.199.163.98:8765`，只写入被 Git 忽略的 `AndroidAgent/dev.properties`；仓库提供 `dev.properties.example` 说明字段。
- FastAPI 必须监听 `0.0.0.0:8765` 才能通过开发机网卡地址访问；若只监听 `127.0.0.1`，模拟器无法通过 `58.199.163.98` 连接。
- Windows 防火墙只应在可信开发网络范围内允许 TCP 8765，完成测试后关闭。
- 本地 HTTP 明文访问只能在 Debug 网络配置中开放，Release 必须使用 HTTPS；
- Release 构建不注入开发中台地址。

Windows PowerShell 联调启动示例（先停止旧的 127.0.0.1 监听进程）：

```powershell
cd MiddleServer
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8765
```
