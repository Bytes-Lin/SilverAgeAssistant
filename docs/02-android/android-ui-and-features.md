# Android UI 与功能说明

## 1. 设计原则

- 大按钮、大字号、高对比；
- 首页固定，避免动态信息流；
- 一屏只强调一个主要任务；
- 语音为主，按钮兜底；
- 每一步都说明“正在听、正在处理、正在播放”；
- 错误文案告诉老人下一步怎么做；
- 涉及金额、药物、身份和求救时必须复述确认。

## 2. 角色入口

首次启动：

- “给老人使用”
- “我是家属”

角色选择页只展示上述两个明确入口，不向实际用户显示“以后可以在设置中更改”等开发期说明。

家属可通过绑定码协助老人配置。老人模式可设置为默认启动角色，避免每次选择。

当前初始化 UI 流程：

```text
角色选择
├── 给老人使用 → 老人基础信息 → 老人首页
└── 我是家属   → 家属基础信息 → 家属首页
```

- 老人基础信息包含称呼、可选的家属手机号、6 位绑定码和状态摘要共享确认；手机号与绑定码必须一起填写，没有绑定资料时允许先进入老人模式。
- 家属基础信息包含家属称呼、家属手机号、老人称呼、老人手机号、关系和紧急联系人选择；关系不提供“配偶”选项。
- Android 已接入家属直接注册、老人档案、一次性绑定码和老人设备绑定接口；注册请求只提交称呼、手机号和幂等 UUID，不再调用开发验证令牌接口。请求失败时停留在表单，只有收到服务端成功响应后才显示“绑定码已生成”或“已绑定”。
- 家属端注册与生成绑定码、老人端手机号和绑定码联合校验均已在本地模拟器完成中台在线联通验证。
- Debug 构建通过 Repository + Preferences DataStore 临时保存双方称呼、手机号、关系、紧急联系人选项和共享确认，便于重复测试；Release 构建禁用该测试持久化。
- 测试 DataStore 从云备份和设备迁移中排除，不保存绑定码、验证码、access/refresh token 或 device credential。
- access/refresh token 和 device credential 使用 Android Keystore AES-GCM 密钥加密后写入独立私有存储，并排除云备份与设备迁移；绑定码只保留在当前进程状态中。
- 正式应用状态使用独立的 Preferences DataStore 保存默认角色、双方初始化完成标记、最后已知绑定状态和最后同步时间；该状态在 Debug 与 Release 构建中均启用，不保存手机号或任何认证凭证。
- 应用启动时先读取正式应用状态和加密凭证：已完成初始化且凭证存在时直接进入对应首页，不再回到注册表单。升级前已安装版本若只有加密凭证，会在首次启动时推断并迁移角色和完成状态。
- 进入首页及应用重新回到前台时，通过 `GET /api/v1/bindings` 后台校验会话。家属 access token 失效时先调用 `/api/v1/auth/refresh`，保存新 token 后重试；普通断网或中台临时故障保留本地首页并显示离线状态，不误清除用户身份。
- 中台明确返回凭证无效、`BINDING_REVOKED`，或已绑定家属的有效绑定列表变为空时，Android 清除对应角色和初始化完成标记，立即清空当前导航栈返回老人/家属身份选择页；老人设备凭证失效时同时清空老人端家属联系人记忆。家属绑定被撤销但家属登录仍有效时保留加密家属会话和老人档案 ID，重新选择家属后直接为原档案生成新绑定码，不重复注册手机号；只有认证本身失效时才清除家属 access/refresh token。

## 3. 老人首页

固定四个主要入口：

1. 和我说话
2. 今日提醒
3. 联系家人
4. 新闻播报

顶部显示日期、天气摘要和最近一条重要提醒；首页不显示录音或“按住说话”按钮，老人通过
宫格中的“和我说话”卡片进入聊天页后再使用语音。

### M01 UI 骨架实现说明

- 应用使用“对话气泡、守护双手和暖色心形”组成的原创银龄助手图标，采用浅杏桃到柔和珊瑚的暖色背景、象牙白主体和深珊瑚心形，营造亲切、可信的照护感。自适应桌面图标与 Android 12 及以上系统启动画面共用该品牌资源，不再显示 Android Studio 默认机器人图标。
- 首次安装先进入老人/家属角色选择页；已经完成初始化并保存有效凭证时，后续启动直接进入相应首页。
- 老人首页使用响应式两列/三列网格，主要按钮最小高度为 72dp，并为聊天、提醒、联系家人、新闻和设置提供语义标签。
- 老人首页进入后使用前台粗略定位查询 Open-Meteo；加载期间、权限拒绝、定位关闭和网络失败都有独立状态，不会用 Mock 天气冒充实时结果。
- 首页优先使用 Android 系统反向地理编码把本次天气查询所用经纬度解析为城市；设备没有可用结果时，端侧直接调用 BigDataCloud 客户端反向地理编码接口。第一行左侧显示解析出的城市，右侧显示当前天气和温度。两级解析都失败时才显示“当前位置”，不得根据时区猜测或硬编码城市。
- 首页同时显示当天高低温、降雨概率和未来三天简报，并标注更新时间与“天气数据：Open-Meteo”。恶劣天气建议由确定性端侧规则生成，不宣称为官方灾害预警。
- 日期行右侧使用对号或叉号展示家人绑定状态；点击图标后再显示绑定正常、离线或失效等详细说明，首页不再单独占用一张绑定状态卡。
- “最近提醒”使用独立卡片，不再放入天气卡；卡片复用提醒 Room 数据，优先显示最新一条未完成事项，只有已完成且完成时间属于当天的记录才继续保留；列表为空时显示“当前没有提醒”。提醒卡使用浅蓝强调色，与紫色天气卡区分。
- 四个首页功能入口只显示图标和名称，移除副说明并压缩卡片高度，使常用入口在普通手机屏幕内完整展示。
- 首页和聊天 `get_weather` Tool 复用同一个端侧 Repository，缓存有效期为 2 小时；缓存期内 Tool 仍会执行，但不会再次访问 Open-Meteo。
- 首页宫格中的“和我说话”卡片进入对话页；首页不再额外渲染底部“点这里和我说话”按钮，
  避免它在聊天返回后的布局重组中被误认为首页录音入口。
- “新闻播报”页直接请求百度热搜公开页面，解析页面内嵌结构化数据并展示前 15 条标题与摘要；加载失败时保留明确提示和手动刷新入口。全局语音开关开启时一次播报前 5 条。
- 首页不再显示“生活助手”和“紧急求助”手动入口；相关生活操作与求助能力由聊天 Agent
  根据老人自然语言意图调用 Tool，不要求老人寻找独立功能页。
- 老人首页“设置”已接入本机模型 API Key 页面。输入框默认隐藏内容，可临时显示以便核对；保存后页面只显示末四位掩码。替换密钥直接输入新值保存，删除密钥必须二次确认。
- API Key 页面仅操作老人设备上的加密凭据存储，不调用中台、不把密钥写入模型配置 JSON，也不提供家属端远程读取入口。

## 4. AI 对话页

文字聊天首版状态机：`Idle → Connecting → Thinking / UsingTool → Responding → Idle`。后续接入语音后再扩展 `Listening / Transcribing / Speaking`。

语音实施采用老人端全局开关：开启后聊天页支持按住说话，最终识别文本复用现有文字消息
和 Agent 链路；流式回复完整结束后，只把最终正文一次提交 TTS 并完整播报。关闭后仍保留
打字与系统手写输入。家属模式不显示
开关、不申请麦克风。家属新通知和新闻播报共用同一播放队列与 AudioFocus，详细设计见
[`../03-agent-system/voice-interaction-design.md`](../03-agent-system/voice-interaction-design.md)。

聊天中老人报告“今天身体不舒服”时，Agent 调用 `report_family_situation` 上报紧急事件；老人明确说“想让儿子回家吃饭”等家庭请求时上报一般事件。普通闲聊、过去已结束的情况、假设问题和他人的状态不上报。事件时间由手机生成，不接受模型提供的时间。

聊天中的“给家人打电话”使用 `call_family_contact` Tool。模型仅识别家属称呼/关系，完整手机号由老人端加密家属快照在本地匹配，不写入 prompt、Tool 返回值或日志。唯一匹配后显示大字本地确认框，确认后才请求电话权限并拨打；权限被拒绝时使用系统拨号页作为降级路径。

页面元素：

- 标题栏右侧只显示上下文圆环和百分数，表示最近一轮输入 Token 占应用上下文上限的比例，不再使用单独状态卡片或“上下文”文字；
- 中部是可滚动对话窗，老人内容以字符串显示在右侧，AI 内容以字符串显示在左侧；
- 底部同时保留语音按钮和文字输入框；
- 文字输入支持“打字”和“手写”模式，两种模式写入同一个字符串草稿；
- 开始/结束录音；
- 停止播放；
- 重播；
- 取消任务。

当前页面展示一条不进入模型上下文的本地欢迎语。打字或系统手写输入发送后，老人字符串立即进入右侧气泡，Android 直接调用配置的 OpenAI 兼容模型，SSE 返回内容逐段进入左侧气泡。手写模式复用 Android 系统输入法：页面负责聚焦文字框并提示用户在手机键盘中切换到“手写”，应用不自建手写识别模型。

生成期间通过回复气泡呈现等待或流式文字，并提供停止按钮；停止后保留部分回复并标记“回答已停止”。失败时显示可理解提示和重试入口。页面不再显示占用一整行的聊天状态卡，也不在底部重复说明。日常聊天关闭模型思考，内置 `get_current_time` 工具用于验证工具调用闭环。老人端全局语音开关开启后，仅“和我说话”页面提供“按住说话”：首次就地申请麦克风权限，授权后提示老人再次按住，不在权限弹窗关闭后自动录音；PCM 只在内存中经 Qwen ASR 转成普通用户字符串。松手事件即使早于 ASR WebSocket 完成连接也会排队执行停止和识别；离开聊天页或应用进入后台会取消 ASR、停止 TTS 并释放麦克风。MLLM 完整回答后再单次调用 Qwen TTS 并播放，流式文字增量不触发合成。GUI 控制条在尚未接入真实语音操作时不显示麦克风占位入口。聊天内容当前只保存在进程内，不写入 Room、中台或日志；Room 只保存不含正文的全局用量记录。

system prompt 会读取老人设备应用私有目录中的 `agent/MEMORY.md`。完成绑定、恢复既有会话以及同步家属联系人时自动更新老人称呼和家属摘要；手机号及其尾号都不进入该文档或模型上下文，只记录“联系方式已在本机安全保存”。后续经老人确认的偏好可继续追加到长期记忆区。

ASR 置信度低或识别出高风险意图时先复述确认。

## 5. 已移除的手动入口

老人首页不再提供“生活助手”和“紧急求助”卡片，避免把已经整合进统一交互流程的能力重复暴露为老人需要理解和寻找的独立入口。对应占位路由不计为已交付产品功能；独立 SOS 倒计时、本地电话/短信/定位与中台协同仍属于后续开发范围。
- “帮我买一袋大米。”
- “查一下快递到哪里了。”
- “帮我打车去医院。”

流程：理解意图 → 获取偏好与约束 → 推荐选项 → 老人选择 → 无障碍执行 → 订单摘要 → 金额确认 → 第三方支付。

推荐依据只使用已确认偏好、预算、配送时间、忌口和历史选择。不得根据未经确认的疾病推断医疗饮食。

GUI Agent 当前已建立异步任务和真机单步操作能力：

- 主聊天 Agent 已通过异步 `gui_agent` Tool 创建任务，Tool 立即返回，不阻塞聊天；
- GUI Todo 只保存任务内容和最少状态元数据，GUI Run 和页面执行现场不持久化；
- 单设备一次只运行一个 GUI 任务；
- 第一次完整运行失败后提示老人，先回到桌面并清理目标 App 的旧任务栈，再从入口页自动
  重试一次；第二次完整失败才进入家属协助出口，并创建
  `GUI_ORDER_ASSISTANCE_REQUIRED / EMERGENCY` 家属紧急事件；该上报由任务管理器确定性
  调用共享 `FamilySituationReporter`，不依赖主聊天模型再次选择 Tool；
- 暂停原因区分老人/主 Agent、离开目标 App 和目标 App 内人工干预；
- 主聊天与 GUI Agent 已接入共享语音协调器和 Qwen ASR/TTS；GUI 覆盖层按住说话只把识别
  文本送入当前 GuiRun，普通步骤只播报下一步操作，商品/订单确认时才播报必要详情；
- 当前支持按包名打开美团、微信和淘宝；只有无障碍观察确认目标 App 已进入前台后，纯打开
  任务才算完成。涉及搜索、普通文本输入、点击和滚动的请求，通过 resize 截图、
  无障碍节点树和独立 GUI MLLM 执行单步 ReAct，每个动作后必须重新观察；
- Android 11+ 使用 Accessibility 截图，Android 10 当前明确提示截图能力不可用，不降级为
  无验证盲点；API 29 MediaProjection 授权路径留待后续实现。

银龄助手前台 Compose 控制条和无障碍系统覆盖层均已实现：左侧按状态显示“暂停/继续/返回任务”，右侧为需要二次确认的“取消”。无障碍覆盖层中间显示受全局开关控制的圆形“按住说话”按钮；关闭开关时按钮禁用且不能调用 GUI ASR/TTS。离开目标 App 后只允许返回任务，回到目标
App 后恢复暂停前阶段。系统覆盖层必须由老人或测试人员在 Android 无障碍设置中明确
启用，不使用额外悬浮窗权限。截图时控制条只短暂隐藏并在 MLLM 推理前恢复，不遮挡上传
图像；启动和 Agent 成功动作后的页面加载事件在有限窗口内抑制，普通页面自动滚动不再直接
视为人工接管，明确触摸开始或非抑制期点击才暂停。目标 App 内 Activity/页面跳转不会暂停；
短暂出现系统或 WebView 过渡窗口时延迟复核，只有目标包持续离开前台才按“离开目标 App”
暂停。

前台识别使用无障碍根节点包名；收到目标 App 窗口事件后立即显示系统控制条。MLLM 截图
保留完整显示区域再按像素预算等比缩小，不使用同包 active window 的局部边界裁剪，避免美团
等多窗口页面只上传首页的一小块区域。

页面点击不依赖固定坐标：执行器优先点击截图对应的当前无障碍节点；动态页面改变树路径时，
使用稳定 `viewId`、文字或内容描述重新匹配实时节点；只有匹配可信但节点不接受
`ACTION_CLICK` 时，才对该实时节点中心执行手势点击。无法重新匹配时重新截图规划，不按旧
位置盲点，所有降级路径继续执行支付与敏感控件拦截。

主聊天 Tool 的 `STARTED` 只表示异步任务创建，主 Agent 只能简短告知“已经开始处理”，
不得据此宣称 App 已打开或页面操作完成。系统悬浮控制条只有在目标 App 启动会话建立后才
显示；复杂任务至少成功执行一个真实动作并取得动作后的新截图，才允许结束任务。
包含美团、微信或淘宝及明确操作动词的指令会在主聊天模型响应前确定性创建 GUI 任务；主
Agent 不先询问商家、口味或规格。需要补充的信息由 GUI Agent 打开 App、观察真实页面后再
询问。仅询问使用方法的句子仍按普通聊天处理，不会自动操作手机。

当 Debug 构建的 `BuildConfig.GUI_DEBUG_ENABLED=true` 时提供进程内 GUI Agent 追踪面板：
银龄助手页面右下角显示“GUI 调试”，跨 App
顶部无障碍控制条显示最新阶段且可点击查看。追踪覆盖主 Agent 是否调用 Tool、Intent 启动、
前台观察、截图尺寸、MLLM 请求与原始 JSON、ReAct 决策和设备动作结果。最多保留最近 100
条，支持手动清空，退出进程即丢失；不保存或展示截图字节，不写文件、Room 或中台。该值由
未入库的 `AndroidAgent/dev.properties` 中 `guiDebugEnabled` 控制，默认 `false`；Release 构建
始终强制为 `false`，不采集也不显示该追踪。

启用 GUI 调试后，面板可在“节点优先（默认）”与“纯坐标实验”之间切换，设置只存在于当前进程。
纯坐标模式下 MLLM 请求不包含 `accessibility_nodes`，所有目标点击必须返回相对上传截图的
`0..1000` 归一化坐标；输入框先用坐标点击取得焦点，再向当前焦点输入。无障碍节点实现不
删除，仍在端侧用于敏感页面、密码、验证码、支付与提交订单的确定性安全拦截。Release 固定
使用节点优先混合模式。协议要求 `x`、`y` 为两个独立数字；解析层兼容常见的二元坐标数组，
但拒绝截断 JSON、越界值或无法完整取得两个坐标的响应。

第二次完整失败进入终态后，系统控制条立即关闭，目标 App 退出前台，银龄助手被重新唤起并
导航回“和我说话”页面。Android 普通应用不能强制停止其他包的进程，因此目标 App 仍可能
保留在系统最近任务中，但不会继续占据屏幕或运行 GUI 自动化。
聊天页通过进程内结果总线接收 GUI 终态并追加简短反馈：成功显示“已完成任务。”；失败且
紧急事件已由中台保存时显示“任务失败，已通知家人。”；事件上报失败时不宣称已经通知。

## 6. 网购/外卖支付规则

- 所有付费订单在提交支付前至少一次明确确认；
- 超过本地配置阈值需要二次确认或家属审批；
- 商品、数量、价格、地址变化后旧确认失效；
- 摘要必须包含商家、商品、数量、地址、总额、额外费用和预计送达；
- Agent 不读取/输入支付密码、验证码或生物识别；
- 支付平台最终确认由老人本人完成。

## 7. 陪伴聊天

支持日常问候、熟悉话题、故事、新闻交流、回忆和简单情绪安抚。回复应短、慢、耐心，不用连续长篇输出。出现持续消极、自伤或急性身体不适表达时，进入安全策略而不是只继续闲聊。

## 8. 日常提醒

类型：用药、复诊、饮水、吃饭、睡眠、测量、社区活动、快递、门窗、燃气、电器。

提醒卡片：

- “我已完成”
- “稍后提醒”
- “联系家人”

“未确认”不等同于“未服药”。提醒计划和执行记录存 Room。

“今日提醒”按以下稳定规则展示：

- 家属下发的未完成提醒一经写入 Room 即持续显示，不因截止时间属于明天、跨时区换算或已经逾期而隐藏；截止时间只决定何时开始本地催办；
- 已完成提醒仅在老人确认完成的当天保留，之后从“今日提醒”移除；
- 未完成和“稍后提醒”的卡片按事件发生/计划时间从早到晚排列；
- “我已完成”的卡片统一放到列表最下方，已完成组内仍按事件时间排列；
- 等待确认使用普通背景，“稍后提醒”使用强调色背景，已完成使用弱化背景和独立状态文字颜色，三种状态不能只靠文案区分；
- 家属即时通知以端侧收到并写入 Room 的时间作为事件时间；远程提醒沿用 `scheduled_at` 作为完成截止时间。截止时仍未完成则发送本地高优先级通知，之后每 1 小时重复，确认完成后取消。

家属通知与远程提醒接入规则：

- 家属端“发送通知”和“创建提醒”已由占位入口改为可提交表单，所有内容必须先写入 FastAPI 中台；
- 家属创建提醒通过系统日期和 24 小时时间选择窗口设置计划，不再手工输入格式；过去日期和同日已过去时间在选择阶段拒绝，提交前仍进行二次校验；
- 老人端使用 device credential 可靠补拉；收到 `COMMAND_AVAILABLE`、WebSocket 首次连接或重连、应用返回前台时自动刷新一次，前台停留在其他页面也能接收新命令。并发提示会合并，不进行短周期轮询；
- 通知收到后以“家人通知”加入当天列表，一次性提醒按服务端 UTC 时间转换为本地时间；
- 本地 Room 以 `command_id` 去重，写入成功后才 ACK，断网时仍可查看已保存提醒；家属提醒首次写入 Room 时还会立即发布老人端系统通知，展示提醒标题、内容和截止时间，REST 重复补拉同一 `command_id` 不会重复通知；
- WebSocket 在上一轮补拉进行中再次提示时只记录待刷新标志，当前轮结束后立即再补拉，不能因并发提示而漏掉后一条通知或提醒；
- 中台通知、提醒、补拉和 ACK 接口已实现并完成双端基础联通测试；Android 仍以 REST/Room 为事实来源，不把 WebSocket 在线提示当作送达结果。
- 老人确认远程提醒完成后端侧先写 Room，并以稳定幂等请求重试上报；中台 completion 与 history 接口及家属提醒记录 Android 页面均已完成。即时通知只负责送达和展示，不进入完成回传。
- 家属端收到 `REMINDER_STATUS_CHANGED` 时自动刷新提醒记录；安全事件提示自动刷新今日状态和紧急事件。应用返回前台及 WebSocket 重连后会补拉可靠 REST 快照，手动刷新仅作为失败兜底。
- 家属创建提醒当前使用家属设备系统时区把日期和时间转换为 UTC。若测试模拟器为 `GMT`、老人真机为 `Asia/Shanghai`，同一个墙上时刻会相差 8 小时；未完成提醒仍会显示，但截止催办时间会按实际 UTC 执行。后续应由中台同步老人设备 IANA 时区并由家属端明确展示。

## 9. 快捷联系与 SOS

联系页不再内置测试对象。它按关系显示中台同步的家属称呼、完整手机号和大号拨号按钮，点击后使用系统 `ACTION_DIAL` 打开拨号页。联系人完整快照先用 Android Keystore AES-GCM 加密保存在应用私有目录并排除云备份；离线时显示上次快照。设备专用同步接口已经在中台实现，契约见 [`../04-middle-server/elder-family-profile-sync-requirements.md`](../04-middle-server/elder-family-profile-sync-requirements.md)。

独立 SOS 功能尚未实现，老人首页也不再提供 SOS 手动按钮。规划中的 SOS 不得依赖中台成功后才执行本地求助。

SOS 并行流程：

- 本地震动和语音确认；
- 短暂取消窗口；
- 本地拨打紧急联系人/进入 120 拨号流程；
- 尝试发送短信与位置；
- 同时向 FastAPI 创建 SOS 事件；
- 页面持续显示已执行步骤。

## 10. 老人异常状态监控

状态监控默认开启、间隔 5 分钟，最后一次有效配置原子保存在 `files/agent/safety-monitor-config.json`。老人端启动后自动运行带常驻通知的独立前台 Agent；家属端可关闭或选择 1/5/10/15/30/60 分钟。在线更新立即生效，修改间隔保留六小时暂存历史，关闭清空历史。配置与暂存状态均排除云备份和设备迁移。

状态监控 Agent 与聊天 Agent 完全分离。开发阶段由 `MockSafetyImageSource` 按稳定顺序读取 `assets/mock/fall_detect`，正式版通过 `NetworkCameraImageSource` 从已授权局域网摄像头获取单张图像，不使用老人手机摄像头。每次检测直连老人配置的 OpenAI 兼容 MLLM，并只接受：

```json
{
  "state": "正常|异常",
  "detail": "异常时必填，正常时省略"
}
```

结果与当前时间保存在六小时端侧窗口。连续第 2 次异常创建本窗口唯一紧急事件并上传触发图像，连续第 3 次异常只发送一次家属短信；后续异常不重复通知或短信。家属端显示缩略图，点击后按授权读取原图进行人工核实。结果必须标注为“疑似/需要核实”，不自动拨打急救电话。

## 11. 新闻播报

老人首页入口现为“新闻播报”，避免测试阶段处理媒体版权与本地媒体授权。首版由老人端直接访问 `https://top.baidu.com/board?tab=realtime`，从页面内嵌 `s-data` JSON 的 `hotList` 中读取 `word`（标题）和 `desc`（摘要），仅展示前 15 条。

页面展示来源、条数、标题和摘要，并提供手动刷新。百度桌面版 `data.cards/hotList` 与移动版 `cards/tabTextList` 均可解析；移动版没有摘要时明确显示“暂无摘要”。网络失败、HTTP 错误和页面结构变化使用不同提示。

新闻使用进程内 2 小时暂存，缓存期内重新进入页面或点击刷新都直接复用数据，不重复访问百度；缓存过期后下一次请求才获取新榜单。缓存时长统一定义在 `CachedNewsRepository.NEWS_CACHE_TTL_MILLIS`。当前不抓取详情页正文。全局语音开关开启时，进入页面读取手机当前本地日期时间，并把前 5 条按“当前是 X 年 X 月 X 日 X 点 X 分，今天的新闻如下。第一条新闻的内容如下：标题。摘要”拼接成一段，发起一次 TTS；页面继续显示前 15 条，并提供停止和重新播报，播报不会触发额外百度请求。

## 12. 新闻、天气与生活提醒

新闻 UI 使用百度热搜公开页面的标题与摘要，不抓取详情页正文；语音开关开启时直接复用同一缓存数据播报前 5 条，不需要再次请求新闻页面。天气卡通过确定性规则显示带伞、减少外出等简短行动建议。

天气首版直接请求 `https://api.open-meteo.com/v1/forecast`，一次取得当前天气、今天及未来三天。Android 只申请 `ACCESS_COARSE_LOCATION`，不申请后台或精确定位；经纬度仅用于直接访问天气服务，不上传中台或放入模型工具结果。

## 13. 家属模式 UI

家属端“状态检测设置”可关闭或选择 1、5、10、15、30、60 分钟并通过中台下发；远程尚无配置时显示默认开启、5 分钟。

家属端“今日状态”只显示一般通知，“紧急事件”只显示紧急通知，列表按老人当地时间从新到旧排序。家属 App 在前台收到 `SAFETY_EVENT_AVAILABLE` 或 `SAFETY_EVENT_IMAGE_AVAILABLE` 后通过 REST 重新拉取；带图事件按授权接口加载缩略图，点击后临时加载原图弹窗，不保存到相册或共享缓存。未确认紧急事件使用不可点击外部消失的弹窗，点击“我知道了”后向中台 ACK。由于不使用第三方移动推送，App 被系统终止时不承诺即时弹窗，恢复前台后用 REST 补拉。

- 老人列表/绑定页；

- 提醒确认时间线；
